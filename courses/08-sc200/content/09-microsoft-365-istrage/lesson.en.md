## Exam objectives: 2.3

Domain 2 (**Respond to security incidents**) is worth 35–40% of the exam. Objective **2.3 Investigate Microsoft 365 activities to identify threats** has three items, and all of them are in this module:

- **Investigate threats by using Microsoft Purview Audit** – unified audit log, Audit (Standard) and Audit (Premium),
- **Investigate threats by using Content search in Microsoft Purview eDiscovery** – finding (and, if needed, deleting) content in mailboxes, SharePoint, OneDrive and Teams,
- **Investigate threats by using Microsoft Graph activity logs** – a trail of all HTTP requests to the Microsoft Graph API in the tenant.

All three tools answer different investigation questions:

| Tool | Question it answers | Where it lives |
|---|---|---|
| **Purview Audit** | *Who did what and when?* (mailbox sign-in, file access, rule change, sharing) | **Microsoft Purview portal** > **Audit** |
| **Content search (eDiscovery)** | *Where is this content?* (which mailboxes received a phishing mail, a document with confidential data) | **Microsoft Purview portal** > **eDiscovery** > **Cases** > **Content Search** |
| **Microsoft Graph activity logs** | *Which API calls did an app or user send to Graph?* | Entra **diagnostic settings** > Log Analytics (table `MicrosoftGraphActivityLogs`) |

Typical exam scenario: a compromised account or OAuth app. Audit shows the *activities*, Graph activity logs show the *API calls made by apps*, and Content search shows the *content* (which mails arrived, where they ended up) and lets you remove it.

## Microsoft Purview Audit

The **unified audit log** records thousands of user and admin activities from Exchange Online, SharePoint Online, OneDrive, Teams, Microsoft Entra ID, Power BI, Copilot and other services. The same records are read from the portal, PowerShell and the API.

### Audit (Standard) vs Audit (Premium)

| Capability | Audit (Standard) | Audit (Premium) |
|---|---|---|
| Enabled by default | yes | yes |
| Audit search tool in the Purview portal | yes | yes |
| `Search-UnifiedAuditLog` cmdlet | yes | yes |
| **Audit Search Graph API** | yes | yes |
| Export results to CSV | up to **50,000** rows | up to **1,000,000** rows |
| Office 365 Management Activity API | baseline bandwidth | about **twice the** bandwidth (per-tenant limit) |
| Default retention | **180 days** | **1 year** for Entra ID, Exchange, OneDrive and SharePoint; everything else 180 days |
| **Audit log retention policies** | no | yes (per service, activity or user, up to 1 year) |
| **10-year** retention | no | yes, with the per-user **10-Year Audit Log Retention add-on** license |
| **Intelligent insights** (e.g. mail access properties, searches in Exchange and SharePoint) | no | yes |
| License | most Microsoft 365 / Office 365 enterprise plans | E5/A5/G5 or Purview Suite / E5 eDiscovery and Audit add-on |

Notes that show up in questions:

- Standard retention was **increased from 90 to 180 days** for logs generated since October 17, 2023.
- 10-year retention is **not retroactive**: it applies only to records generated after the policy is created.
- Records generated by non-user entities (service principals, system events) are kept for a fixed **one year**, and custom policies do not apply to them.
- With Audit (Premium), the `MailItemsAccessed` activity gets the **`SensitivityLabel`** property (the sensitivity label of the accessed mails). The Premium license must be assigned to the **user** whose activities are recorded.

> **On the exam:** "Investigating a compromised mailbox requires audit records that are 10 months old and proof of which mails the attacker accessed." You need **Audit (Premium)** (one year for Exchange by default) and `MailItemsAccessed` records. With Audit (Standard), records older than 180 days no longer exist, and no later license change brings them back.

### Checking whether audit is enabled

Audit is enabled by default, but an administrator can turn it off. The check is done in **Exchange Online PowerShell**:

```powershell
Get-AdminAuditLogConfig | Format-List UnifiedAuditLogIngestionEnabled
# True = audit log search is enabled

Set-AdminAuditLogConfig -UnifiedAuditLogIngestionEnabled $true
```

Trap: the same cmdlet also exists in **Security & Compliance PowerShell**, but there `UnifiedAuditLogIngestionEnabled` always shows `False`, even when audit is enabled.

### Roles

| What | Required role |
|---|---|
| Searching the audit log in the Purview portal | **Audit Logs** or **View-Only Audit Logs** (Purview) |
| `Search-UnifiedAuditLog` in PowerShell | **Audit Logs** or **View-Only Audit Logs** in the **Exchange admin center** |

Access can be scoped with **administrative units**: a restricted admin sees and exports only the logs of users in their admin units, while an unrestricted admin sees everything, including non-user and system accounts.

### Searching in the portal

Path: **purview.microsoft.com** > **Audit** card (if it is missing: **View all solutions** > **Core** > **Audit**) > **Search**.

| Field | Note |
|---|---|
| **Date and time range (UTC)** | defaults to the last 7 days, maximum **180 days** per search |
| **Keyword Search** | searches only the indexed *common schema* part of the record |
| **Admin Units** | limits the search to admin units |
| **Activities - friendly names** | activity groups with readable names |
| **Activities - operations names** | exact operation names, comma separated, e.g. `MailItemsAccessed,New-InboxRule` |
| **Record types** | e.g. `ExchangeItem`, `SharePointFileOperation`, `MIPLabel` |
| **Search name** | job name in the search history |
| **Users** | empty = all users and service accounts |
| **File, folder, or site** | part of a name or URL, wildcard `*` only at the end |
| **Workloads** | Exchange, SharePoint, Teams… |

A search is a **search job** that runs in the background:

- it keeps running after you close the browser,
- a user can have **up to 10 jobs at the same time**, of which **one without filters**,
- completed jobs are kept for **30 days**,
- in large tenants a broad search can take **up to 48 hours**,
- **Copy this search** copies the criteria into a new search, and **Export** exports the results to CSV.

A record shows up in the audit log with a delay: for Exchange, SharePoint, OneDrive and Teams usually **60–90 minutes**, and longer for other services. Microsoft does not guarantee an exact time.

> **On the exam:** "Five minutes ago a user shared a file outside the organization, and a search in Audit returns nothing. What is the most likely reason?" The audit log ingestion delay (60–90 minutes for the main services). Nothing needs to be enabled and no license needs to change.

### Programmatic access

| Method | When |
|---|---|
| `Search-UnifiedAuditLog` (Exchange Online PowerShell) | ad hoc searches and scripts; same backend as the portal |
| **Audit Search Graph API** | programmatic search through Microsoft Graph |
| **Office 365 Management Activity API** | continuous retrieval into a SIEM or long-term storage |
| **Microsoft 365 connector** in Sentinel | Exchange, SharePoint and Teams activities in the `OfficeActivity` table |

```powershell
Search-UnifiedAuditLog -StartDate (Get-Date).AddDays(-7) -EndDate (Get-Date) `
  -UserIds ana@contoso.com -Operations MailItemsAccessed,New-InboxRule -ResultSize 5000
```

### What to look for with a compromised account

| Operation | Why it matters |
|---|---|
| `MailItemsAccessed` | which mails were accessed (scope of the leak) |
| `New-InboxRule`, `Set-InboxRule`, `UpdateInboxRules` | rules that forward or hide mails (typical for BEC) |
| `Set-Mailbox` with `ForwardingSmtpAddress` | forwarding the whole mailbox externally |
| `Add-MailboxPermission` | delegated access to someone else's mailbox |
| `FileDownloaded`, `FileAccessed` | mass download from SharePoint/OneDrive |
| `SharingSet`, `AnonymousLinkCreated` | sharing outside the organization |
| `Consent to application.` (Entra) | a user consented to an OAuth app |
| `Add member to role.` (Entra) | privilege escalation |

### The same data in Sentinel and Defender

When the **Microsoft 365** connector is enabled, Exchange, SharePoint and Teams records go to the **`OfficeActivity`** table. In Defender advanced hunting, similar activities are in **`CloudAppEvents`** (through the Defender for Cloud Apps connector for Microsoft 365).

```kql
// New inbox rules that forward or delete mails (last 7 days)
OfficeActivity
| where TimeGenerated > ago(7d)
| where OfficeWorkload == "Exchange"
| where Operation in ("New-InboxRule", "Set-InboxRule")
| where Parameters has_any ("ForwardTo", "RedirectTo", "DeleteMessage", "MoveToFolder")
| project TimeGenerated, UserId, ClientIP, Operation, Parameters
| sort by TimeGenerated desc
```

```kql
// Mass file downloads per user per hour
OfficeActivity
| where TimeGenerated > ago(1d)
| where OfficeWorkload in ("SharePoint", "OneDrive")
| where Operation == "FileDownloaded"
| summarize Downloads = count(), Files = dcount(OfficeObjectId) by UserId, ClientIP, bin(TimeGenerated, 1h)
| where Downloads > 200
```

```kql
// The same question in Defender advanced hunting
CloudAppEvents
| where Timestamp > ago(1d)
| where Application == "Microsoft SharePoint Online"
| where ActionType == "FileDownloaded"
| summarize Downloads = count() by AccountDisplayName, IPAddress, bin(Timestamp, 1h)
| where Downloads > 200
```

> **On the exam:** the "which table to use" question for Exchange/SharePoint activities: in Sentinel it is `OfficeActivity`, in Defender advanced hunting `CloudAppEvents`. `AuditLogs` is the Entra ID audit (directory changes), and `SigninLogs` are sign-ins – both are wrong answers for "who downloaded a file from SharePoint".

## Content search in Purview eDiscovery

**Content search** finds content *where it lives* (in-place) in Microsoft 365 sources:

- Exchange Online mailboxes,
- SharePoint sites and OneDrive accounts,
- Microsoft Teams and Microsoft 365 groups,
- Viva Engage.

### Content Search in the new eDiscovery experience

Classic Content Search has been retired and merged into the unified **eDiscovery** experience in the Purview portal. Existing searches live in a special case called **Content Search**:

**purview.microsoft.com** > **eDiscovery** > **Cases** > **Content Search** > **Create a search**

| | Content Search case | Full eDiscovery case |
|---|---|---|
| Search and statistics | yes | yes |
| Export results | yes | yes |
| **Holds** (content preservation) | no (since February 2026) | yes |
| **Review sets** | no (since February 2026) | yes (Premium features with E5) |
| Who sees it | admins choose the members of the Content Search case | case members |

Since February 2026, Content Search is meant as a simple "find and export" tool. If the investigation needs evidence preservation (hold) or analysis in a review set, you create a full eDiscovery case. Microsoft has also announced that containers with exported search data expire after **14 days**, so download the export right away.

### Roles

| What | Role or role group |
|---|---|
| Creating and running a search | **eDiscovery Manager** role group or the **Compliance Search** role |
| Access to all cases | **eDiscovery Administrator** (a member of the eDiscovery Manager group with elevated rights) |
| Deleting found mails (purge) | the **Search And Purge** role or **Organization Management** in the **Purview portal** |

The split is intentional: one person can search, and another can delete. **Organization Management** in *Exchange Online* is not the same as the group with the same name in *Purview* and does not grant the right to delete.

### Creating a search

1. **Create a search**, enter a unique name and description, **Create**.
2. On the **Query** tab, add **Data sources**: users, groups, sites or **All people and groups** for the whole tenant. For a user you can also add related sources (manager, direct reports, groups they are a member of, frequent collaborators).
3. Build the query:
   - **Condition builder** – fields and conditions without writing syntax,
   - **KeyQL** editor – paste complex queries, with error checking,
   - **Draft a query with Copilot** (preview) – Security Copilot turns natural language into KeyQL.
4. **Run query** and choose how to view the results:
   - **Statistics** – estimated number of items by location, item type, sensitive information; the **query keywords report** shows how many hits each part of the query returns,
   - **Sample** – a representative sample: **1, 10 or 100** items per location, from **10, 100, 1000 or 10,000** locations.
5. Review the results, refine the query (or **Duplicate** the search to keep the original) and export.

### KeyQL rules that get tested

| Rule | Example |
|---|---|
| Operators **AND, OR, NOT, NEAR** must be UPPERCASE | `phishing AND invoice` |
| A space between expressions means **OR** | `from:"Sara Davis" subject:reorganization` = one OR the other |
| `property:value` with **no space** after the colon | `to:pilarp` (while `to: pilarp` is just a plain word) |
| **Prefix** wildcard only | `invoic*` works, `*voice` and `in*ce` do not |
| Quotes for multiple words | `subject:"Action required"` |
| Minus excludes | `-from:"Sara Davis"` |
| Item type | `kind:email`, `kind:im`, `kind:microsoftteams` |
| Date | `received:2026-10-01..2026-10-03` |
| Site with a trailing slash | `path:sites/HelloWorld/` |
| Search is **case-insensitive** | `Apple` = `apple` |
| **An empty query returns EVERYTHING** from the selected sources | always add at least one condition |

Time in searches is always **UTC**.

```text
(received:2026-10-13..2026-10-14) AND (subject:"Action required") AND kind:email
(from:billing@contoso-invoices.com) AND (attachmentnames:*.html OR attachmentnames:*.htm)
```

> **On the exam:** "The query `subject: invoice from:attacker@evil.com` returns too many results." Two mistakes: the space after `subject:` turns the condition into a plain word, and the space between expressions means **OR**. Correct: `subject:invoice AND from:attacker@evil.com`.

### Search and purge: removing a phishing mail

When Content search finds a malicious mail in mailboxes, it can be deleted. The procedure is meant for **incidents** (phishing, malware, data leaks), not for cleaning up mailboxes.

1. Connect to **Security & Compliance PowerShell** (EXO module 3.9.0+, `Connect-IPPSSession -EnableSearchOnlySession`).
2. Create and run the search (portal or PowerShell). The search must include **only mailboxes and public folders**, not sites.
3. Check the number of results (`Get-ComplianceSearch`) and, if possible, create an **export report** to see exactly what will be deleted.
4. Run the purge and track the status.

```powershell
Connect-IPPSSession -EnableSearchOnlySession

$s = New-ComplianceSearch -Name "Remove Phishing Message" -ExchangeLocation All `
  -ContentMatchQuery '(Received:10/13/2026..10/14/2026) AND (Subject:"Action required")'
Start-ComplianceSearch -Identity $s.Identity
Get-ComplianceSearch -Identity "Remove Phishing Message" | Format-List Status,Items

New-ComplianceSearchAction -SearchName "Remove Phishing Message" -Purge -PurgeType SoftDelete
Get-ComplianceSearchAction -Identity "Remove Phishing Message_Purge"
```

| | SoftDelete | HardDelete |
|---|---|---|
| Where the message ends up | **Recoverable Items\Deletions** | **Purges** folder |
| User can restore it | yes (until deleted item retention expires) | no |
| Permanent deletion | after retention | after retention (single item recovery) and Managed Folder Assistant processing |

Limits:

| Limit | Value |
|---|---|
| Items per location in one purge (PowerShell, case without Premium features) | **10** |
| Items per location through Microsoft Graph (case with Premium features) | **100** |
| Maximum mailboxes in a search used for purge | **50,000** (otherwise use search permissions filters) |
| SharePoint and OneDrive | not supported |
| Teams messages | this cmdlet does not delete them (separate procedure for Teams) |
| Mailbox on hold | the message is removed from view but kept for as long as the hold lasts |
| Unindexed items | not deleted |

If the organization has **Defender for Office 365 Plan 2**, Microsoft recommends a different path: **Threat Explorer** > **Take action** (soft/hard delete, move to junk, move to inbox) with approval in the **Action center**. It is faster, works with more messages and stays in the incident history (module 08).

> **On the exam:** "An analyst has eDiscovery Manager and tries `New-ComplianceSearchAction -Purge`, but gets an error that the Purge parameter does not exist." The **Search And Purge** role in the Purview portal is missing. Adding them to Exchange Online Organization Management does not help.

## Microsoft Graph activity logs

**Microsoft Graph activity logs** are an audit trail of **all HTTP requests** that Microsoft Graph receives and processes for the tenant: from line-of-business apps, SDKs, scripts, AI clients (including the **Microsoft MCP Server for Enterprise**, whose requests have `/enterprise` in `RequestUri`) and Microsoft apps (Outlook, Teams, admin portals).

The audit log says *what was changed*. Graph activity logs say *which API call was sent, who sent it, from which IP address, with which token and what the response was*, including **reads** (e.g. an app listing all users or reading mails), which are often not visible in the audit log.

### Prerequisites and enabling

| Requirement | Value |
|---|---|
| License | **Microsoft Entra ID P1 or P2** |
| Least privileged Entra role for diagnostic settings | **Security Administrator** |
| Destination | **Log Analytics workspace**, **Storage account** (List Keys) or **Event Hubs** |

Path: **Microsoft Entra admin center** > **Monitoring & health** > **Diagnostic settings** > **Add diagnostic setting** > category **MicrosoftGraphActivityLogs** > **Send to Log Analytics workspace** (the workspace Sentinel runs on).

Limitations to know:

- **It cannot be filtered** in diagnostic settings. To reduce cost, use a **workspace transformation** (DCR on the table) or move the table to a cheaper plan (Basic / data lake tier).
- Events usually arrive within **30 minutes**, rarely up to **2 hours**.
- Only requests to **your** tenant are visible. You do not see the activities of your multitenant app in someone else's tenant.
- Logs are not collected retroactively: they are recorded only from the moment you enable them.

> **On the exam:** "An app is suspected to be compromised and to have read mails through the Graph API. Entra audit logs show nothing. What should you enable?" A diagnostic setting with the **MicrosoftGraphActivityLogs** category to a Log Analytics workspace (requires Entra ID P1/P2). Audit logs record changes, not individual read API calls.

### The MicrosoftGraphActivityLogs table

| Column | Meaning |
|---|---|
| `TimeGenerated` | time the request was received |
| `RequestUri`, `RequestMethod` | which endpoint and which method (GET, POST, PATCH, DELETE) |
| `ResponseStatusCode` | 200, 401/403 (no permission), 429 (throttling) |
| `AppId`, `ServicePrincipalId` | the app sending the request |
| `UserId` | the user (for delegated calls); empty for app-only |
| `IPAddress`, `UserAgent`, `Location` | where the request came from and which region processed it |
| `Scopes` / `Roles` | delegated permissions / application permissions from the token |
| `SignInActivityId` | link to the sign-in record (`UniqueTokenIdentifier` in the sign-in logs) |
| `ClientAuthMethod` | 0 public client, 1 client secret, 2 certificate |
| `RequestId`, `OperationId` | request and batch identifiers |
| `Wids` | the user's tenant-wide roles |

### KQL examples

```kql
// Entities with the most denied requests to /groups (401/403) – reconnaissance without permissions
MicrosoftGraphActivityLogs
| where TimeGenerated >= ago(3d)
| where ResponseStatusCode in (401, 403)
| where RequestUri contains "/groups"
| summarize UniqueRequests = dcount(RequestId) by AppId, ServicePrincipalId, UserId
| sort by UniqueRequests desc
| take 20
```

```kql
// Which resources risky users read or changed (Entra ID Protection)
MicrosoftGraphActivityLogs
| where TimeGenerated > ago(30d)
| join kind=inner (AADRiskyUsers | project Id, RiskState, RiskLevel) on $left.UserId == $right.Id
| extend Path = tostring(parse_url(RequestUri).Path)
| summarize Requests = dcount(RequestId) by UserId, RiskState, Path, RequestMethod, ResponseStatusCode
```

```kql
// Linking API calls to the sign-in (IP, device, Conditional Access)
MicrosoftGraphActivityLogs
| where TimeGenerated > ago(7d)
| join kind=leftouter (
    union SigninLogs, AADNonInteractiveUserSignInLogs, AADServicePrincipalSignInLogs
    | where TimeGenerated > ago(7d)
  ) on $left.SignInActivityId == $right.UniqueTokenIdentifier
```

```kql
// An app reading mails in bulk (possible exfiltration through the Graph API)
MicrosoftGraphActivityLogs
| where TimeGenerated > ago(1d)
| where RequestMethod == "GET"
| where RequestUri has "/messages"
| summarize Calls = count(), Users = dcount(UserId), IPs = make_set(IPAddress, 10) by AppId, bin(TimeGenerated, 1h)
| where Calls > 1000
| sort by Calls desc
```

```kql
// Apps getting throttled (429) – unusual volume
MicrosoftGraphActivityLogs
| where TimeGenerated > ago(3d)
| where ResponseStatusCode == 429
| summarize Throttled = count() by AppId, RequestMethod
| sort by Throttled desc
```

### Typical investigation flow for a compromised OAuth app

1. An alert (e.g. Defender for Cloud Apps or Entra ID Protection) points to a suspicious app or user.
2. **Purview Audit** / `AuditLogs`: when consent was granted (`Consent to application.`), when a secret or certificate was added to the app, which roles were assigned.
3. **Graph activity logs**: what the app called after that (`/users`, `/me/messages`, `/drives`), from which IP address, with which permissions (`Roles`, `Scopes`).
4. **Content search**: if the app sent phishing from the compromised mailbox, find and remove those messages at the recipients.
5. Remediation: revoke consent and secrets, disable the service principal, reset the user's credentials, revoke sessions.

> **On the exam:** a question about ordering or choosing tools. Key: **who did what** → Audit; **which API call** → Graph activity logs; **where the content is and remove it** → Content search (or Threat Explorer with MDO P2).

## Comparison: which tool for which requirement

| Requirement in the scenario | Tool |
|---|---|
| Find all mailboxes that received a mail with a specific subject | **Content search** |
| Export one user's mails for the legal team | **Content search** (export) or eDiscovery case |
| Preserve a user's content while the investigation is running | **eDiscovery case with a hold** (not Content Search) |
| Determine who created a forwarding inbox rule | **Purview Audit** |
| Prove which mails the attacker accessed | **Purview Audit** (`MailItemsAccessed`) |
| Keep audit records for 7 years for regulatory reasons | **Audit (Premium)** + 10-year add-on + retention policy |
| See which Graph endpoints an app called and from which IP address | **Graph activity logs** |
| A Sentinel detection for bulk reading through the API | **Graph activity logs** in the workspace + analytics rule |
| Continuously send audit data to a SIEM | **Office 365 Management Activity API** / Microsoft 365 connector |

## Summary

- **Purview Audit**: enabled by default (check with `Get-AdminAuditLogConfig` in **Exchange Online** PowerShell). Standard = **180 days**, export of 50,000 rows. Premium = **1 year** for Entra/Exchange/OneDrive/SharePoint, retention policies, 10 years with the add-on (not retroactive), export up to 1,000,000, higher API bandwidth, intelligent insights.
- Search: **Purview portal > Audit > Search**, a background job, max **180 days** per search, **10 jobs** at the same time, jobs kept for **30 days**. Roles **Audit Logs** / **View-Only Audit Logs**. Ingestion delay 60–90 min.
- In Sentinel, Exchange/SharePoint/Teams activities are in `OfficeActivity`; in advanced hunting, in `CloudAppEvents`.
- **Content search** is now the **Content Search** case in unified eDiscovery: search and export, without holds and review sets (a full case is needed for those). KeyQL: uppercase operators, space = OR, `property:value` with no space, prefix wildcard only, empty query = everything.
- **Search and purge**: `New-ComplianceSearchAction -Purge -PurgeType SoftDelete|HardDelete`, the **Search And Purge** role in Purview, 10 items per location (100 through Graph), max 50,000 mailboxes, Exchange only. With MDO P2, use Threat Explorer.
- **Graph activity logs**: Entra ID P1/P2, diagnostic setting **MicrosoftGraphActivityLogs** (Security Administrator), table `MicrosoftGraphActivityLogs`, no filtering in diagnostic settings, delay up to 2 h; link to sign-ins through `SignInActivityId` = `UniqueTokenIdentifier`.
